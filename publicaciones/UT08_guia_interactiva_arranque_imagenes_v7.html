1 · Particiones

Una partición es una región delimitada de un disco. Puede contener un sistema de archivos o servir para funciones especiales; un directorio organiza archivos dentro de un sistema de archivos. La tabla de particiones describe dónde empiezan y terminan las particiones. PDF, pp. 3–5.

ConceptoMBR (clásico)GPT (actual)
TablaEsquema tradicional con hasta 4 entradas primarias; admite una extendida y particiones lógicasTabla GUID; no usa extendidas/lógicas como MBR
ArranqueHabitualmente BIOS heredada con código de arranque en MBRHabitualmente UEFI con partición de sistema EFI (ESP)
Uso didácticoExplica los esquemas antiguos que aparecen en el PDFRepresenta muchos equipos modernos

Explora un esquema de particiones

Precaución: el gráfico es una simulación. Redimensionar, eliminar o formatear particiones reales puede causar pérdida de datos. Antes de hacerlo, identifica el disco y conserva una copia verificada. El PDF utiliza ejemplos antiguos de /dev/hda; en equipos modernos son frecuentes /dev/sda o /dev/nvme0n1.
Procedimiento práctico: identificar sin modificar discos
  1. Windows: abre diskmgmt.msc y observa discos, volúmenes, tamaños y particiones EFI/recuperación.
  2. Linux: consulta lsblk -f y sudo parted -l para identificar dispositivos, sistemas de archivos y tablas.
  3. Compara los identificadores de partición y los tamaños. No confundas la letra C: con el disco completo.
  4. Antes de editar, confirma qué disco estás seleccionando y prepara copia de datos.

2 · Instalación y opciones de arranque

Instalar un sistema operativo exige preparar un medio de instalación, arrancar desde él, elegir el disco de destino y completar la configuración inicial. Se distinguen las instalaciones en un equipo físico y en una máquina virtual. Ampliación práctica a partir de la UT08, pp. 6–13; los procedimientos detallados para equipos físicos y los enlaces oficiales son material complementario.

BIOS / UEFI

Firmware que inicializa el equipo y determina desde qué dispositivo o entrada de arranque se inicia. En UEFI es habitual usar una partición de sistema EFI (ESP).

USB de instalación

Un archivo ISO contiene la imagen de instalación. Debe escribirse como USB arrancable: copiar el archivo ISO al USB sin más no suele bastar.

Gestores de arranque

Windows Boot Manager y GRUB gestionan el arranque según el sistema y la configuración. En un arranque dual se requiere planificación adicional.

Antes de comenzar: haz copia de los archivos y verifica que puedes restaurarlos; identifica el disco de destino por modelo y capacidad; comprueba requisitos del sistema, licencia cuando corresponda, firmware UEFI/BIOS, Secure Boot y posibles claves de recuperación del cifrado. Formatear o eliminar particiones borra datos. Para una primera práctica, utiliza una máquina virtual o un disco de ensayo.

Guías prácticas por fases (despliega la que necesites)

1 · Preparación: descargar las ISO y elegir un procedimiento oficial
  1. Identifica el sistema que vas a instalar y si el equipo admite su arquitectura y requisitos. Anota edición y versión prevista.
  2. Windows 11: descarga la ISO oficial o utiliza la herramienta Crear medios de instalación de Microsoft, que puede preparar directamente el USB. La licencia y los requisitos del equipo deben corresponder a la edición elegida.
  3. Ubuntu Desktop: descarga la ISO desde Canonical y, si el proveedor facilita sumas de verificación, verifica la descarga cuando proceda.
  4. Elige un USB cuya capacidad cumpla el mínimo indicado en las instrucciones del sistema; se borrará su contenido. Comprueba que no es el disco de copia de seguridad.
  5. Consulta la documentación del fabricante del equipo para comprobar menú de arranque, ajustes UEFI y almacenamiento (por ejemplo, controladores de almacenamiento especiales).

2 · Preparar el USB con Rufus: procedimiento y parámetros

Rufus escribe una ISO en una memoria USB para que el firmware pueda arrancar desde ella. Es útil tanto para Windows como para Ubuntu; en Windows 11 Microsoft ofrece además su herramienta propia de creación de medios.

  1. Descarga Rufus desde rufus.ie (sitio oficial) y ejecútalo en Windows. Conecta el USB que vas a borrar.
  2. En Dispositivo, elige el USB exacto comprobando su capacidad. No selecciones un SSD o HDD con datos que quieras conservar.
  3. En Selección de arranque, pulsa Seleccionar y abre la ISO oficial previamente descargada.
  4. Revisa el esquema de partición y sistema de destino: para un equipo UEFI moderno suele corresponder GPT / UEFI; MBR / BIOS se usa solo cuando el equipo realmente emplea arranque heredado compatible. No cambies opciones por intuición: el modo de arranque del equipo y el soporte preparado deben ser compatibles.
  5. Comprueba las opciones propuestas por Rufus para la ISO concreta. En Ubuntu sigue la guía oficial de Canonical para responder al modo de escritura, si aparece. En Windows, no actives opciones para omitir requisitos de hardware como práctica predeterminada.
  6. Pulsa Empezar, lee las advertencias de borrado y espera a que el estado indique Listo. Expulsa el USB de forma segura.
Rufus no crea una copia de seguridad ni instala todavía el sistema en el PC: prepara el medio de arranque. Las opciones visibles varían según ISO, versión de Rufus y firmware.

3 · Arrancar desde el USB: menú de arranque y configuración UEFI/BIOS
  1. Apaga correctamente el ordenador, conecta el USB arrancable y enciéndelo.
  2. Durante el inicio, usa la tecla del menú de arranque temporal indicada por el fabricante. Puede ser F12, F9, Esc u otra: no hay una tecla universal.
  3. Elige la entrada correspondiente al USB, preferiblemente la indicada como UEFI: nombre del USB cuando la instalación sea UEFI. El menú de arranque temporal normalmente evita modificar el orden permanente.
  4. Si no aparece el USB, comprueba la escritura de la ISO, el puerto, la compatibilidad UEFI/BIOS y las indicaciones del fabricante. Entra en la configuración del firmware solo cuando sea necesario y documenta cualquier cambio.
  5. Cuando aparezca el instalador, comprueba el idioma y la opción deseada. No selecciones ni borres particiones hasta identificar inequívocamente el disco destino.
En UEFI, la ESP aloja archivos de arranque, mientras que el orden y las entradas se gestionan desde el firmware. Secure Boot no debe desactivarse automáticamente para instalar Windows 11 o un Ubuntu compatible. Si el equipo tiene protección de firmware o cifrado, consulta su documentación antes de modificar ajustes.

4 · Instalación de Windows 11 en un equipo físico
  1. Arranca desde el USB de instalación oficial (Rufus con ISO oficial, o herramienta de creación de medios de Microsoft).
  2. Selecciona idioma, teclado y región conforme a los cuadros del instalador; el aspecto puede variar según versión.
  3. Elige instalar Windows; introduce la clave de producto si corresponde o utiliza la opción que proceda a tu licencia digital. Selecciona la edición correcta y acepta las condiciones.
  4. Decide entre mantener una instalación existente mediante un procedimiento de actualización admitido, o realizar una instalación limpia. En esta última, seleccionar y eliminar particiones del disco destino puede borrar irreversiblemente todos sus datos.
  5. En la selección de disco, comprueba modelo, tamaño y estructura de particiones. Si hay varios discos o un arranque dual, detente y revisa el plan de particionado antes de confirmar.
  6. Deja que el instalador copie archivos y reinicie el equipo. Cuando corresponda, evita volver a arrancar el instalador desde el USB.
  7. Completa la configuración inicial (cuenta, red, privacidad), instala actualizaciones y controladores desde Windows Update y el fabricante del equipo.
  8. Verifica activación, administrador de dispositivos, disco y modo de arranque. Crea un punto de recuperación cuando proceda y documenta el resultado.
Windows 11 requiere cumplir sus requisitos oficiales, incluidos UEFI y otras condiciones de seguridad. Una reinstalación limpia no es lo mismo que una reparación de inicio ni que una restauración de archivos. Para conservar aplicaciones y datos, consulta la ruta de reinstalación adecuada en la guía oficial antes de iniciar.

5 · Instalación de Ubuntu Desktop en un equipo físico
  1. Descarga la ISO de Ubuntu Desktop y crea el USB arrancable; Canonical explica el proceso con Rufus cuando partes de Windows.
  2. Arranca desde el USB en modo compatible con el firmware. Usa Probar Ubuntu si quieres comprobar Wi-Fi, pantalla, teclado y otros dispositivos antes de instalar.
  3. Inicia la instalación, selecciona idioma, accesibilidad, distribución de teclado y conexión de red según la versión del instalador.
  4. Elige las opciones de instalación que procedan (aplicaciones y software adicional). Algunas opciones dependen de la versión de Ubuntu.
  5. En el apartado de disco, distingue borrar disco e instalar, instalar junto a otro sistema si se ofrece, o particionado manual. Comprueba cuidadosamente el disco de destino; no asumas que la propuesta automática conserva todos los datos.
  6. Si se comparte el equipo con Windows, verifica primero BitLocker, espacio libre, modo UEFI, ESP y advertencias del instalador. Sigue la documentación específica de arranque dual antes de cambiar particiones o ajustes de almacenamiento.
  7. Selecciona zona horaria y crea el usuario y contraseña. Revisa el resumen y confirma solo tras verificar las operaciones de disco.
  8. Finaliza la instalación, reinicia, retira el USB cuando se solicite y comprueba actualizaciones, conectividad, particiones y arranque.
Importante para arranque dual: la instalación en un disco compartido con Windows tiene riesgos adicionales; no aconsejamos desactivar BitLocker o cambiar el modo del controlador de almacenamiento sin un procedimiento específico y una copia verificada.

6 · Laboratorio VirtualBox: instalar y comparar ambos sistemas sin tocar el equipo físico

En VirtualBox se usa el mismo instalador, pero la ISO se monta como unidad óptica virtual y el destino es un disco virtual. El procedimiento es ideal para practicar sin modificar particiones reales.

  1. Instala VirtualBox desde el proveedor y descarga las ISO oficiales.
  2. Crea una VM con memoria, CPU y disco virtual suficientes, eligiendo conscientemente UEFI o BIOS virtual antes de instalar.
  3. Monta la ISO como medio de arranque y sigue el asistente de Windows o Ubuntu, seleccionando el disco virtual.
  4. Para arranque dual, crea un plan de particiones y deja espacio para el segundo sistema sin borrar las particiones del primero.
  5. Comprueba el arranque y los sistemas de archivos. Crea una instantánea antes de ensayar cambios que puedan afectar al arranque.
  6. Documenta capturas del disco virtual, esquema de particiones y gestor de arranque.

4 · Restauración de datos: recuperar archivos desde una copia

Este apartado continúa el trabajo de Copias de seguridad. Partimos de un equipo con Windows o Ubuntu en funcionamiento y de una copia previa de archivos personales que está guardada en un disco USB externo u otro destino accesible. Queremos recuperar un documento borrado, perdido o modificado. PDF, pp. 26–27. Desarrollo práctico complementario para 1.º SMR.

Secuencia que seguiremos en todas las prácticas

1 · Identificar copia → 2 · Conectar origen → 3 · Elegir versión → 4 · Restaurar en destino seguro → 5 · Comprobar

La restauración lee del soporte que contiene el backup y escribe en una carpeta de destino. No es lo mismo que hacer una nueva copia.

Ejemplo inicial: el lunes guardaste trabajo.txt en la copia externa. El jueves lo modificaste o borraste del equipo. Restaurar significa volver a obtener una versión del archivo desde la copia del lunes, sin necesidad de reinstalar Windows o Ubuntu.

Cuatro guías desplegables

1 · Identificar la copia de seguridad que tenemos

Antes de restaurar, responde: ¿dónde está la copia?, ¿cuándo se realizó?, ¿qué archivos contiene?, ¿qué herramienta la generó?, ¿quiero recuperar un único archivo, una carpeta o una versión anterior?

Importante: «completa», «incremental» y «diferencial» describen estrategias de copia. No son tres botones universales de restauración. El procedimiento exacto depende del programa y del formato utilizado. Si el USB contiene archivos corrientes, basta con copiarlos; si contiene un backup gestionado, normalmente se usa la herramienta que lo creó.
2 · Restauración manual: copiar archivos desde un USB

Es el caso más fácil para entender el concepto: la copia externa contiene archivos visibles en carpetas, sin formato especial de backup.

  1. Conecta el USB y comprueba en el explorador que la unidad es la correcta. Identifica su capacidad, nombre y contenido.
  2. Abre Explorador de archivos en Windows o Archivos en Ubuntu y localiza la carpeta de la copia.
  3. Identifica el archivo y revisa, si es posible, su fecha y contenido.
  4. Crea en el equipo una carpeta nueva, por ejemplo Documentos/Restauracion_Prueba.
  5. Utiliza Copiar y después Pegar en esa carpeta. No uses «Mover» ni elimines el archivo que está en el USB.
  6. Abre el archivo restaurado y compara su contenido con el esperado. Anota qué archivo recuperaste, origen, destino y resultado.
Resultado esperado: el archivo aparece tanto en el USB (la copia sigue disponible) como en el equipo (archivo restaurado). Este caso sirve para explicar la restauración, pero no recupera por sí mismo versiones históricas que no estén guardadas por separado.
3 · Windows 10/11: restaurar con Historial de archivos

Punto de partida: ya configuraste Historial de archivos y existe al menos una copia en una unidad externa. Si todavía no tienes una copia, vuelve a la guía de copias de Windows; no se puede restaurar un archivo que nunca fue respaldado.

  1. Conecta el disco utilizado para Historial de archivos. Comprueba que Windows lo reconoce.
  2. Abre el Panel de control y entra en Sistema y seguridad → Historial de archivos (los nombres pueden variar ligeramente).
  3. Selecciona Restaurar archivos personales. Si Windows no encuentra las copias, revisa la unidad y la opción para seleccionar otra unidad o una copia existente.
  4. Navega por las carpetas protegidas y utiliza las flechas de versiones/fechas para localizar el documento deseado.
  5. Para la práctica, evita sobrescribir el documento actual: utiliza la opción de restaurar en una ubicación alternativa cuando esté disponible (por ejemplo, desde el menú contextual del botón Restaurar, «Restaurar en»), y elige Documentos/Restauracion_Prueba. Si restauras en su ubicación original, revisa con cuidado cualquier aviso de reemplazo.
  6. Abre el archivo restaurado, comprueba su contenido e identifica de qué fecha es la versión recuperada.
¿Qué hace la herramienta? Permite explorar y recuperar versiones conservadas de archivos protegidos. No restaura por este procedimiento una instalación completa de Windows ni sustituye a una imagen del disco.

4 · Ubuntu: restaurar con Déjà Dup (Copias de seguridad)

Punto de partida: ya creaste una copia de tus archivos con Déjà Dup y sabes en qué USB o ubicación se encuentra. La interfaz y algunas opciones cambian según la versión de Ubuntu y Déjà Dup.

  1. Conecta el USB en el que guardaste las copias y asegúrate de que Ubuntu lo ha montado y puede leerlo.
  2. Abre Copias de seguridad (Déjà Dup) desde el menú de aplicaciones.
  3. Entra en la opción de Restaurar o de recuperar archivos. Si la copia no aparece, indica la ubicación del almacenamiento utilizado cuando se creó.
  4. Espera a que la herramienta examine las copias disponibles y selecciona la fecha/versión que quieres recuperar.
  5. Selecciona los archivos o carpetas que deseas restaurar. Si la copia estaba cifrada, introduce la contraseña correspondiente.
  6. Cuando permita elegir destino, selecciona una carpeta de ensayo, por ejemplo ~/Documentos/Restauracion_Prueba, en lugar de sobrescribir inmediatamente los originales.
  7. Finaliza la restauración y abre el documento recuperado. Comprueba fecha, contenido y ubicación.
Déjà Dup no suele guardar los documentos como una carpeta normal lista para copiar: administra un repositorio de copias y puede cifrarlo. No borres archivos internos del repositorio ni olvides la contraseña. Consulta la ayuda de tu versión si no aparece el mismo botón.

Práctica guiada · copia.txt: crear versiones, perder un archivo y recuperarlo
Objetivo: comprobar en un equipo de ensayo cómo Historial de archivos guarda versiones de un mismo documento y cómo recuperar una concreta desde un USB externo, sin perder la copia de seguridad. Duración: a realizar en una o varias sesiones; no hace falta esperar a días reales.

Material: Windows 10/11, una memoria o disco USB con espacio suficiente, Bloc de notas y acceso al Panel de control. Usa exclusivamente documentos de prueba. No utilices el USB si contiene archivos importantes que no estén respaldados.

Antes de empezar: Historial de archivos no ofrece un selector «completa / incremental / diferencial». En las ejecuciones posteriores guarda nuevas versiones de los archivos protegidos que han cambiado: no registra necesariamente solo los caracteres añadidos. Tampoco incluye automáticamente cualquier carpeta; crea copia.txt dentro de una carpeta que esté protegida y verifica que se incluye en la copia.

Parte A · Crear y guardar la primera versión (lunes simulado)

  1. Dentro de una carpeta incluida en Historial de archivos (por ejemplo, Documentos si está protegida), crea copia.txt. En Bloc de notas escribe Lunes versión 1. Guarda y cierra.
  2. Conecta el USB. En Panel de control → Sistema y seguridad → Historial de archivos, comprueba que la unidad seleccionada es la correcta. Activa la función si todavía está desactivada.
  3. En la pantalla principal, pulsa Ejecutar ahora si aparece disponible; si es la primera activación, espera a que finalice la primera copia. Comprueba que ya figura una copia realizada. Los nombres exactos de opciones pueden variar.
  4. Abre Restaurar archivos personales y verifica que copia.txt está disponible con el texto de la versión 1. Esta es la comprobación esencial: no basta con que la función aparezca activada.

Parte B · Modificar el archivo y guardar otra versión (martes simulado)

  1. Abre el mismo archivo copia.txt en el equipo, conserva su primera línea y añade debajo Martes versión 2. Guarda y cierra.
  2. Vuelve a Historial de archivos y pulsa Ejecutar ahora para forzar una nueva ejecución, sin tener que esperar al intervalo programado. Comprueba que ha terminado.
  3. En Restaurar archivos personales, localiza copia.txt y utiliza las flechas o fechas disponibles para observar las dos versiones. Si no aparecen, comprueba que el archivo está protegido, que se guardó el cambio y que la segunda copia finalizó.
¿Qué se habrá guardado en el USB?

El Historial de archivos normalmente organiza sus datos dentro de una carpeta FileHistory, manteniendo versiones con referencias a fecha y hora. Un .txt suele seguir siendo un archivo de texto; puede encontrarse con un nombre modificado para distinguir versiones. No es un fichero de «solo diferencias» entre las líneas. La estructura concreta depende del usuario, equipo y versión de Windows; para restaurar versiones utiliza preferentemente su interfaz.

Parte C · Simular la pérdida y restaurar (miércoles simulado)

  1. Tras verificar que la versión del martes se puede localizar en el historial, crea una carpeta de destino Documentos\Restauracion_Prueba.
  2. Para simular el problema, renombra el archivo original del equipo a copia_original_resguardada.txt o muévelo a otra carpeta temporal. Así no arriesgas perder el documento durante la práctica. En el lugar original, copia.txt ya no estará disponible.
  3. Conecta o conserva conectado el USB y abre Historial de archivos → Restaurar archivos personales. Busca copia.txt y selecciona la versión del martes.
  4. Usa Restaurar en (si aparece mediante el menú contextual del botón de restauración) y elige la carpeta de ensayo. Evita sobrescribir el original de prueba. Si tu versión de Windows no ofrece esa opción, revisa el destino y los avisos antes de confirmar.
  5. Abre el archivo recuperado. Comprueba que contiene ambas líneas. Si deseas contrastar, repite la operación seleccionando la versión del lunes y recupérala en otra carpeta para no reemplazar la del martes.

Parte D · Automatización, desconexión y avisos

  1. En Configuración avanzada de Historial de archivos, revisa la frecuencia de las copias y la conservación de versiones. Anota los valores; no existe aquí un selector general de copia «incremental» o «diferencial».
  2. Desconecta el USB de forma segura y comprueba que la herramienta no puede escribir nuevas copias en él. Cuando se reconecte, no presupongas que una copia se inicia instantáneamente: ejecuta Ejecutar ahora para realizarla de forma controlada o espera a la programación.
  3. Windows puede avisar de problemas con una unidad desconectada, pero no garantiza un recordatorio configurable del tipo «avísame el viernes si no conecté el USB». Para eso se necesita una tarea o recordatorio aparte, y sigue siendo necesario verificar que la copia se completó.
Resultado esperado: el alumno puede mostrar una versión del lunes y otra del martes del mismo copia.txt, recuperar la del martes sin sobrescribir su archivo resguardado y demostrar que las dos líneas se han recuperado correctamente.

5 · Clonación de equipos

Una clonación reproduce un disco o partición en otro destino. Una imagen guarda el contenido en archivos para restaurarlo después. La unidad dedica especial atención a Clonezilla Live. PDF, pp. 28–37.

Disco → disco

Copiar un disco de origen a otro disco. El destino puede perder su contenido anterior.

Disco → imagen

Guardar una imagen del sistema en otro medio; sirve para archivado o recuperación posterior.

Imagen → disco

Restaurar la imagen en un disco; normalmente sobrescribe las particiones del destino.

Elige el objetivo

Operación potencialmente destructiva: en clonación o restauración, el disco de destino puede sobrescribirse. La herramienta no ejecuta operaciones reales; para la práctica utiliza preferiblemente máquinas virtuales o discos de ensayo.
Itinerario de Clonezilla Live: instalación/arranque y utilización
  1. Descarga la ISO oficial de Clonezilla Live y revisa el procedimiento oficial para preparar USB de arranque.
  2. Arranca desde el medio Live; no hace falta instalar Clonezilla en el disco del sistema.
  3. Escoge idioma y teclado. Selecciona Start Clonezilla.
  4. Selecciona device-image para guardar/restaurar imágenes, o device-device para copiar directamente un disco a otro.
  5. En modo imagen, selecciona el soporte de almacenamiento local_dev u otro destino compatible, y verifica dónde se guardará la imagen.
  6. Elige savedisk/saveparts para crear imágenes; restoredisk/restoreparts para restaurarlas.
  7. Identifica el disco por modelo, tamaño e identificador antes de confirmar. Verifica la imagen guardada cuando la opción esté disponible.

En el PDF se propone omitir la comprobación de la imagen; como criterio docente actual, es preferible verificarla para comprobar que la copia no está dañada.
