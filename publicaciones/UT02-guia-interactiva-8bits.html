¿Cómo funciona un ordenador?

Del hardware y la memoria hasta los registros y las instrucciones que ejecuta la CPU. Aprende con ejemplos, esquemas y una simulación que puedes controlar.

Una idea clave para todo el tema: un ordenador recibe datos, los almacena, ejecuta instrucciones sobre ellos y produce resultados. Cada componente interviene en alguna parte de ese recorrido.

01 Hardware y software

Dos caras de un mismo sistema: elementos físicos e instrucciones que les indican qué hacer.

🖥️

Hardware

Son los componentes físicos: placa base, procesador, memoria RAM, SSD, pantalla, teclado o fuente de alimentación.

Son los programas y los datos: sistema operativo, navegador, aplicaciones y archivos. El software utiliza el hardware para realizar tareas.

Entrada

Salida

Monitor, altavoces e impresora: muestran resultados.

Entrada y salida

Ejemplo: al escribir en un procesador de textos, el teclado introduce información; la CPU la procesa; la RAM mantiene datos durante el trabajo; el monitor muestra el documento y el SSD permite guardarlo.

02 Arquitectura de Von Neumann

El modelo básico que explica cómo se organizan CPU, memoria y entrada/salida.

04 La CPU y sus registros

La CPU coordina la ejecución de programas. Sus diferentes partes colaboran en cada instrucción.

Unidad de control (UC)

Coordina la búsqueda, interpretación y ejecución de instrucciones y genera las señales de control necesarias.

Unidad aritmético-lógica (ALU)

Realiza operaciones aritméticas (como sumas) y lógicas (como AND y comparaciones).

Registros esenciales del modelo didáctico

Registro¿Para qué sirve?
CP / PC · Contador de programaGuarda la dirección de la siguiente instrucción.
RI / IR · Registro de instrucciónConserva la instrucción que se interpreta o ejecuta.
AC · AcumuladorGuarda operandos o resultados en modelos sencillos.
RE · Registro de estadoContiene indicadores como cero, acarreo y desbordamiento.
RDM / MARRegistro de dirección de memoria: señala una posición de memoria.
RIM / MDRRegistro de intercambio de datos con memoria.

Los nombres y el reparto exacto de registros dependen de la arquitectura. Se presentan aquí como modelo para comprender el ciclo de instrucción, siguiendo la terminología de la UT02.

Importante: 3 GHz significa unos 3.000 millones de ciclos de reloj por segundo, no necesariamente 3.000 millones de instrucciones u operaciones. El rendimiento depende también de la arquitectura, los núcleos, la memoria y otros factores.

06 Memoria RAM, almacenamiento y firmware

No todo lo que guarda información funciona de la misma forma.

⚡

RAM

Memoria principal, rápida y volátil. Mantiene programas y datos mientras se utilizan.

💾

SSD / HDD

Almacenamiento no volátil para conservar aplicaciones y archivos cuando se apaga el equipo.

🔧

Firmware

Código de bajo nivel que inicializa o controla hardware. En equipos modernos, el firmware UEFI suele almacenarse en memoria flash.

¿Y qué son ROM, PROM, EPROM y EEPROM?

Son tecnologías de memoria no volátil que se estudian para comprender la evolución de los circuitos y del firmware. La ROM clásica se leía sin modificarse en uso normal; PROM se programa una vez; EPROM puede borrarse con luz ultravioleta; EEPROM se borra eléctricamente. La memoria flash es una familia de EEPROM con borrado por bloques.

No confundas un pendrive con una ROM clásica: el pendrive utiliza memoria flash regrabable. Tampoco la ROM es la «otra RAM» de uso habitual de un PC moderno.

Direcciones, bytes y palabra

En la memoria direccionable por bytes, cada dirección señala normalmente un byte (8 bits). Una palabra es un grupo de bits cuyo tamaño depende del contexto y de la arquitectura; no significa siempre ocho bytes ni ocho celdas.

Ejemplo: 0x1000 identifica una dirección; el procesador puede leer varios bytes consecutivos para formar un dato de 16, 32 o 64 bits.

07 ¿Qué significan 32 y 64 bits?

Una distinción importante, pero conviene evitar simplificaciones que llevan a errores.

Concepto32 bits (x86, modo clásico)64 bits (x86-64/AMD64)
Registros generales32 bits64 bits
Espacio de direcciones virtuales típico del procesoLimitado en el modelo habitual de 32 bitsMucho mayor en sistemas modernos
Memoria RAM física utilizableDepende también de PAE, sistema operativo y hardwareDepende de CPU, placa base y sistema operativo
VelocidadNo se puede deducir que un procesador de 64 bits sea el doble de rápido por tener registros de 64 bits.

Con 32 bits se pueden representar 2³² direcciones diferentes (4 GiB si cada dirección corresponde a un byte). Sin embargo, no es una regla universal sobre toda la RAM física: existen extensiones como PAE. De forma equivalente, que una CPU sea de 64 bits no implica que implemente las 2⁶⁴ direcciones físicas posibles.

En el entorno habitual de PC, x86-64, x64 y AMD64 se utilizan para referirse a la arquitectura de 64 bits compatible con x86. No son el nombre de cualquier arquitectura de 64 bits: ARM64 es otra familia.

08 Del botón de encendido a una aplicación

El software no aparece mágicamente en la CPU: hay una secuencia de inicio y carga.

Paso 1

Firmware

Al encender, el firmware inicializa elementos del hardware y prepara el arranque.

Paso 2

Sistema operativo

Un gestor de arranque y el núcleo del sistema operativo toman el control.

Paso 3

Aplicaciones

Al abrir un programa, el sistema carga sus instrucciones y datos a memoria y la CPU los ejecuta.

La documentación original dice que «lo primero que se ejecuta es el sistema operativo». Para el encendido completo es más preciso explicar que primero interviene el firmware y después arranca el sistema operativo.

Retos para comentar en clase

¿Por qué una aplicación guardada en el SSD necesita RAM para ejecutarse?

Porque, en el modelo habitual, la CPU accede a las instrucciones y datos en memoria principal. El sistema operativo carga allí las partes necesarias del programa desde el almacenamiento.

¿Por qué el PC puede arrancar aunque la RAM esté vacía tras apagarlo?

El firmware se conserva en almacenamiento no volátil. Al encender, prepara la máquina y permite iniciar el proceso de carga del sistema operativo en RAM.

¿Un reloj de 4 GHz implica exactamente 4.000 millones de instrucciones por segundo?

No. Los ciclos de reloj no equivalen de forma fija a instrucciones completas: depende de la microarquitectura y del trabajo realizado.
